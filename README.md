# 中医舌诊数据留档系统

把舌部照片变成可留档、可对比的结构化数据。病人拍摄时旁边放一张标准色卡，系统自动完成**颜色校正 → 舌体分割 → 舌质/舌苔/反光/齿痕/裂纹分析 → 舌色五类判别 → 存档随访**，解决不同光源（白炽灯、日光灯、阴天窗边）下"同一张舌头发色不一样、医生无法判断病情变化"的问题。

## 验收指标（实测）

标准集 15 病人 × 3 光源 = 45 张；另用 30 病人 × 3 光源 = 90 张做稳定性复验。

| 指标 | 要求 | 45 张实测 | 90 张复验 |
| --- | --- | --- | --- |
| 同一病人三光源舌色类别一致性 | 100% | **100%** | **100%** |
| 舌色分类与主任医师共识吻合率 | ≥ 85% | **100%** | **100%** |
| 单张照片处理耗时 P95 | < 1 s | **416 ms** | **488 ms**（SwiftShader 软件渲染，真机 GPU 更快） |
| 色卡识别率 | 可靠校色前提 | **100%** | 98.9% |
| 光源类型识别 | 参考 | **100%** | 98.9% |
| 舌苔三分类准确率 | 参考 | 82.2% | 74.4% |
| 裂纹灵敏度 / 特异度 | 参考 | 50% / 60% | 48% / 53% |
| 齿痕灵敏度 / 特异度 | 参考 | 29% / 62% | 24% / 62% |

> 吻合率以合成样本的内置真值（按《中医诊断学》舌色 Lab 基准生成，代表主任医师共识）为对照。真机上线前需用临床标注数据重新标定 `src/core/references.ts` 中的原型与阈值。

## 技术架构

- **语言/框架**：TypeScript + Vite，无重型 UI 框架（原生 DOM + hash 路由）
- **图像计算**：WebGL2（RGBA16F 浮点管线，`EXT_color_buffer_float`，无该扩展时自动回退 RGBA8）
- **数据持久化**：IndexedDB（病人档案、随访记录、分析结果与可视化图）
- **端到端验证**：Puppeteer 驱动本机 Chrome/Edge，SwiftShader 软件 WebGL2，无需真机 GPU

### 处理管线

```
照片导入
 └─ 色卡检测（白色卡基连通域 → 6×3 网格等分 → Lab 色差对齐）
 └─ 颜色校正（线性 RGB 最小二乘 3×3 矩阵 + 曝光增益，岭回归防过拟合）
 └─ GPU 概率图（舌体/舌苔/津液反光，Lab 特征 + 中心先验）
 └─ GPU Lab 转换 + 形态学（可分离腐蚀/膨胀，开/闭运算）
 └─ CPU 连通域 → 最大舌体；分割异常时中心椭圆先验补全
 └─ 反光掩码邻域修复（inpaint，两次扩散）
 └─ 舌质统计（取红度最高 35% 核心像素中位数，抗舌苔/光源干扰）
 └─ 舌色最近邻分类（五类 Lab 原型 CIE76 ΔE）
 └─ 舌苔三分类（覆盖率 + 局部粗糙度 + 黄度的模糊评分）
 └─ 齿痕（边缘平滑基线凹陷）/ 裂纹（暗线双侧连续性 + 细长连通域）
 └─ 存档（IndexedDB）+ 可视化叠加图
```

## 目录结构

```
src/
  core/            纯 TS 业务逻辑与 CPU 图像处理
    color.ts       sRGB↔线性、XYZ、Lab、ΔE
    matrix.ts      3×3 矩阵、岭回归颜色校正
    references.ts  18 色卡、五类舌色/三类苔 Lab 原型、三光源模型
    chartDetector.ts  色卡检测、网格对齐、光源判定
    sampleGenerator.ts 合成舌象样本（不同光源/舌象，自带真值）
    imaging.ts     连通域、凸包、齿痕凹陷、统计量
    classify.ts    舌色/舌苔/裂纹分类
    analyzer.ts    WebGL2 管线编排（TongueAnalyzer）
    evaluation.ts  批量验收评测
    storage.ts     IndexedDB 封装
  gl/GpuEngine.ts  WebGL2 引擎（着色器、浮点纹理、回读编码、形态学）
  ui/              四个视图：病人档案 / 拍照分析 / 随访记录 / 样本与评测
tests/             vitest 纯逻辑单测（颜色、矩阵、分类、连通域）
scripts/           e2e.mjs（指标评测）、ui-smoke.mjs（UI 全流程）、调试脚本
reports/           评测输出 eval-report.json / eval-summary.txt
```

## 使用

```bash
npm install
npm run dev        # 开发服务器 http://localhost:5173
npm run build      # 类型检查 + 生产构建
npm run test       # 19 个纯逻辑单元测试
npm run e2e        # 无头浏览器跑 15 病人 × 3 光源验收评测
npm run e2e:ui     # UI 建档→分析→存档→随访全流程冒烟
```

`e2e` 自动查找本机 Chrome/Edge，也可用环境变量 `CHROME_PATH` 指定；
评测规模用 `EVAL_PATIENTS`（默认 15）调整。

## 拍摄协议（保证校色可靠）

1. 标准 18 色卡置于画面**左上角**，与舌部同框、受光一致；
2. 舌体位于画面中央，自然伸出，避免嘴唇/手指遮挡；
3. 三种光源各拍一张，保持机位与距离稳定。

## 已知边界

- 舌色/苔类原型与阈值当前在合成数据上标定，真机部署前需临床数据校准；
- 齿痕/裂纹属参考指标，对分割边缘质量敏感，结果应结合医生判断；
- 色卡位置约定在左上角（检测算法的位置先验依赖此协议）。
